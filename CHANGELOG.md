# Changelog

## [Unreleased]

### Добавлено (Фаза 12 — Фундамент)

- Закреплённые заметки теперь рендерятся отдельной секцией сверху списка (задача 12.4,
  закрывает риски **R6**/**R7**): long-press по заметке открывает меню из трёх пунктов —
  «Закрепить»/«Открепить», «Переместить», «Удалить заметку» (`NoteRow` — иконка `pin.fill` 11dp
  рядом с заголовком); `NotesViewModel`/`FolderViewModel` делят поток заметок на
  `pinnedNotes`/`unpinnedNotes` в коде (порядок `updatedAt DESC` внутри каждой группы не меняется),
  а `togglePin` вызывает точечный `NoteRepository.setNotePinned` (из задачи 12.3), не трогая
  `updatedAt`. Пункт «Переместить» открывает `MoveFolderSheet` для одной заметки — новые
  `moveNote`/`createFolderAndMoveNote` в обоих ViewModel'ях зеркалят существующие
  `moveSelectedNotes`/`createFolderAndMoveSelected`, переиспользуя тот же
  `NoteRepository.moveNotesToFolder`; мультивыбор со своим независимым состоянием
  `showMoveSheet` не затронут. Пункт «Удалить» подключён к тому же `onDeleteNote`, что и
  свайп-удаление — без отдельного диалога подтверждения. Общая логика строки (режим выбора,
  свайп-удаление, long-press меню) вынесена в `ui/components/NoteListSection.kt` — единый
  `LazyListScope`-расширитель для `NotesListScreen` и `FolderScreen`, устраняющий дублирование
  двух экранов. Во время поиска секции не показываются — один плоский список, как и раньше.
- `BibleReference.formatVerseSpec` — компактная запись списка стихов (`"14-16,20"`) с настраиваемым
  разделителем диапазона; по умолчанию ASCII-дефис, который `BibleReferenceParser` может прочитать обратно
  (риск **R2**: `compactVerseString` для экрана по-прежнему использует en dash `–`, непригодный для текста заметки).
- `BibleReference.coveredVerses` — раскрывает ссылку в список номеров стихов (`verseList`, если он есть,
  иначе диапазон `verseStart..verseEnd`, иначе пусто для ссылки на всю главу).
- `BibleReference.replacementText` — пересобирает текст ссылки под новый набор стихов, сохраняя
  сокращение книги ровно так, как его набрал пользователь.
- Room-миграция `AppDatabase` версии 1 → 2 (закрывает риск **R1**): добавлена автомиграция
  (`AutoMigration(from = 1, to = 2)`) вместо сборки без `addMigrations`/`fallbackToDestructiveMigration`.
  Колонка `notes.isPinned` (`Boolean`, SQL-default `0`) едет вместе с этим bump'ом версии — она нужна
  задаче 12.3, отдельный bump ради пустой миграции не нужен. Проверено `MigrationTest`
  (`app/src/androidTest/.../data/db/MigrationTest.kt`): существующие заметки переживают миграцию,
  `isPinned` по умолчанию `false`.
- Для инструментальных тестов миграций подключена `androidx.room:room-testing`; androidTest-классам
  добавлен доступ к экспортированным JSON-схемам (`app/schemas`). Также форсирована версия
  `kotlinx-serialization-core`/`-json` до `1.8.1` для androidTest-конфигураций — Compose BOM
  (`2026.05.01`) жёстко фиксирует `1.7.3`, а `room-testing` 2.8.4 требует API из `1.8.1`
  (`GeneratedSerializer.typeParametersSerializers()`); без форса `MigrationTestHelper` падал с
  `AbstractMethodError`.
- Пикер книг Библии для Синодального перевода (`synodal`) показывает Новый Завет в православном
  порядке (задача 12.6): соборные послания (Иакова, 1–2 Петра, 1–3 Иоанна, Иуды) идут сразу после
  Деяний, до посланий апостола Павла — вместо западного протестантского порядка по `id`.
  Новая чистая функция `BibleDatabaseService.applyBookOrder(books, translation)` переставляет только
  список для отображения; `book_id`, SQL-запросы и ссылки на стихи в заметках не меняются.
  Условие строго `translation == "synodal"` (KJV сохраняет западный канонический порядок).
  `fetchAllBooks(translation)` применяет её к результату запроса. Покрыто
  `SynodalBookOrderTest` (4 теста, чистый JVM без обращения к SQLite).

### Исправлено (Данные — Синодальный перевод)

- Обновлён Синодальный перевод (synodal): исправлены глобальные несостыковки в исходном XML-файле (31178 → 31162 стихов).
- `BibleDatabaseService.DB_VERSION` поднята до 3 — при обновлении приложения база данных перекопируется из assets автоматически.
- Подсветки стихов существующих пользователей сохраняются: перед перекопированием базы данные `verse_highlights` бэкапируются и восстанавливаются после.
### Добавлено

- Поддержка запятых в ссылках на стихи: `Быт 1:2,5`, `Быт 1:2-3,5`, `Быт 1:2,5,19`.
  Парсер теперь распознаёт несмежные стихи; шторка стиха отображает только указанные стихи.
  Заголовок шторки компактно отображает список: `Бытие 1:2,5` или `Бытие 1:2–3,5`.

### Обновлено (Брендинг)

- Иконка приложения и сплеш-экрана переработана: спиральный блокнот в янтарном цвете (#C29A3D) на пергаментном фоне (#F6EFE4) — как в iOS-версии.

### Исправлено (Фаза 11 — Баг-фиксы)

- **B1** — Многострочные библейские ссылки теперь корректно тапаются (`BibleEditText`).
  Touch-handler переработан: вместо проверки только первой строки спана используется
  трёхветочная логика (первая строка / последняя строка / средние строки).

- **B2** — Устранено мигание пустой заметки в списке при немедленном выходе из редактора.
  SQL-запросы `observeRootNotes` и `observeNotesInFolder` теперь фильтруют заметки
  с пустым заголовком и пустым контентом (`NoteDao`).

- **B3** — Восстановлен фокус и позиция курсора в редакторе после смены ориентации экрана.
  Добавлен `CursorTrackingEditText` (подкласс `EditText` с `onSelectionChanged`),
  позиция курсора сохраняется через `rememberSaveable` в `NoteEditorScreen`.

- **B4** — Режим выбора теперь доступен при любом количестве заметок (было: только при 2+).
  Условие изменено с `rootNotes.size > 1` на `rootNotes.isNotEmpty()` (`NotesListScreen`).

- **B5** — Системная кнопка «Назад» в пикере книг Библии теперь закрывает пикер,
  а не уходит с экрана Библии. Добавлен `BackHandler` в `BibleReaderScreen`.

- **B6** — Системная кнопка «Назад» на экране выбора переводов (онбординг) больше не
  возвращает на слайды онбординга. Навигация изменена на `popUpTo("onboarding")
  { inclusive = true }` в `MainActivity`.
